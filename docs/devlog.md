### T01 기기 기술 검증 (PR #1)
- `/lab`: 기기 정보, 녹음, 기사 이미지, 영상 A(MediaRecorder)/B(WebCodecs+Mediabunny)/C(ffmpeg.wasm), 사진첩 저장, 사진, 속도·하이라이트, 결과 복사
- 개발 PC에서 A·B·C 모두 동작. B는 1fps면 실시간보다 약 5배 빠름. ffmpeg 워커는 Turbopack 문제로 `public/ffmpeg/`에서 원본 제공
- 안드로이드 1차 시도는 네이버 앱 인앱 브라우저였고 기록이 사라짐 → 기록을 브라우저에 저장하고 접속 환경을 표시하도록 수정
- 결론: **휴대폰 합성으로 간다, 서버 합성(R2) 미도입.** 근거에 팀 내 "옛이야기 마당 인증 영상" 앱(3분 미만 휴대폰 처리 운영 중)
- **개발 단계 분리**: 1단계 = 영상 합성 외 전부, 2단계 = 영상 합성 모듈(V01, 테스트팀·외주 가능). 출시는 한 번
- 녹음 최대 길이는 "휴대폰 합성이 안정적인 길이"로 V01에서 확정, 임시 5분. 기사 170~200단어라 아이 낭독은 3분을 넘을 수 있음
- 카메라 영상 녹화 + 템플릿 합성은 첫 출시 제외. 영상 이미지는 주차별 템플릿 이미지

### T02 데이터 계층 (PR #2)
- 테이블 14개, 집계 함수(진도·관리자 목록·독려 대상·알림 받는 사람·완주 단계), 독려 3회 상한·환불 시 링크 폐기 트리거, RLS, 샘플 데이터(학습자 8명 + 재수강·늦은 완주용 0기)
- Docker가 없어 PGlite(Node에서 도는 PostgreSQL 18)로 검증
- 결정: 수강 상태 `paid`/`refunded`, 환불 처리 `requested`→`approved`/`rejected`(관리자 확인 후 수동), 지난 주차 소급 허용·시작 전 주차 불가, 종강일은 완주 단계 판정에만, 누적 낭독 단어는 영어만, 보호자 = 결제자 번호(숫자만, 고유), 재수강생이 새 기수 환불 시 링크 유지·그 기수 페이지만 가림
- 운영 DB에 마이그레이션과 **샘플 데이터** 적용(개강 전 `supabase/sample-cleanup.sql`로 삭제)

### T03 접속 링크·세션 + 학생 홈 (PR #3)
- `/a/<토큰>` → 해시 확인 → 세션 쿠키(원문 미저장) → 링크 없는 주소로 이동. 보호자 링크 = 자녀 전부(형제 프로필 고르기), 자녀 링크 = 본인
- 홈: 주차 카드, 오늘 학습하기, 종강·완주 진행, 12주 기록(펼침), 라이브 카드, 하단 탭
- 임시 적용: 링크 여러 번 사용, 세션 180일, 새 링크 보내도 이전 링크 유지. 다시 들어가기(인증번호)는 개강 후. 결제 직후 데이터 구조(결정 5)는 첫 접속 작업 때

### 낭독 화면 (PR #4)
- 활동 선택(요일 추천, 지난 주차, 작성 중·이어서) → 1 듣기 → 2 낭독(3초 카운트다운, 하이라이트, 30초 전 안내, 5분 자동 정지) → 3 확인 → 완료
- 녹음은 서버가 준 짧은 유효시간 주소로 Storage 비공개 버킷 `media`에 직접 업로드. 첫 영어 낭독 팝업
- 음원·시간 정보 파일이 아직 없어 하이라이트는 예상 시간(목업과 같음)

### 작성 활동 + 인스타 올리기 (PR #5)
- 작성 활동: 작성지 받기 → 쓰기 안내 → 사진(고르자마자 2048px로 줄여 업로드, 이어서 가능) → 완료. VOCA는 단어 낭독 녹음도 가능
- 인스타 올리기: 올릴 것 목록, 사진 저장(공유 창/내려받기), 영상 저장은 `lib/video` 연결 규칙만 호출(2단계), 링크 붙여넣기 → 인증. 같은 게시물 두 번 인증 금지
- 활동 API를 `/api/activity/*`로 통합
