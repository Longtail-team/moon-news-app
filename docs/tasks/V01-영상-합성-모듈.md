# V01 영상 합성 모듈 (개발 2단계)

브랜치: `feat/video-module`  
결과물: `lib/video/` 모듈 + `/lab` 시험 화면 + 기기 시험 결과(`docs/spike-results.md` 갱신)  
담당: 테스트팀 또는 외주. 앱의 다른 부분(로그인, DB, 화면)을 몰라도 작업할 수 있게 경계를 나눴다.

## 1. 하는 일

낭독 녹음 파일과 주차별 인스타 템플릿 이미지를 받아, 인스타그램에 올릴 MP4를 **휴대폰 브라우저 안에서** 만들고 사진첩에 저장한다.
서버로 보내 만들지 않는다(spec.md 10장, 16장). 카메라 영상 녹화는 범위가 아니다(첫 출시 제외).

## 2. 연결 규칙 (1단계 앱과의 경계)

1단계 앱은 아래 함수만 부른다. 이름과 형태를 바꿔야 하면 먼저 제안한다.

```ts
// lib/video/index.ts

/** 녹음 최대 길이(초). 이 모듈의 기기 시험으로 확정한다. 1단계 녹음 화면이 자동 정지에 쓴다. */
export const MAX_RECORDING_SEC: number;

/** 이 기기에서 영상을 만들 수 있는지 미리 확인. false면 앱은 외부 브라우저 안내 등을 보여준다. */
export function canMakeVideo(): Promise<{ ok: boolean; reason?: string }>;

export type MakeVideoInput = {
  audio: Blob;           // 휴대폰이 녹음한 그대로 (audio/mp4 또는 audio/webm). 길이 ≤ MAX_RECORDING_SEC
  image: Blob;           // 인스타 템플릿 이미지 (1080×1350 PNG). 학습자 이름 등 글자는 앱이 얹어서 넘긴다
  fileName: string;      // 예: "새벽달영어뉴스_1주차_영어낭독.mp4"
  signal?: AbortSignal;  // 취소
  onProgress?: (p: { stage: "prepare" | "encode" | "finalize"; ratio: number }) => void; // ratio 0~1
};

export type MakeVideoResult = { file: File; durationSec: number; method: string; ms: number };

export type VideoErrorCode =
  | "UNSUPPORTED"   // 이 브라우저에서 불가
  | "DECODE_FAILED" // 녹음 파일을 읽지 못함
  | "ENCODE_FAILED" // 인코딩 실패
  | "BACKGROUNDED"  // 만드는 중 화면이 꺼지거나 다른 앱으로 감
  | "ABORTED";      // 사용자가 취소

export class VideoError extends Error { code: VideoErrorCode; }

export function makeVideo(input: MakeVideoInput): Promise<MakeVideoResult>;

/** 사진첩 저장. 공유 창이 되면 공유 창, 안 되거나 파일이 너무 크면 내려받기. */
export function saveVideo(file: File): Promise<"shared" | "downloaded" | "cancelled">;
```

지켜야 할 것
- `lib/video/` 밖의 코드를 고치지 않는다. 외부 라이브러리는 이 폴더에서만 쓴다.
- 녹음·영상을 서버로 보내지 않는다. 로그에 파일 내용, 이름, 연락처를 남기지 않는다(사용자 대부분 만 14세 미만).
- 화면 문구는 앱이 정한다. 모듈은 오류 코드만 돌려준다.

## 3. 출발점 (이미 있는 것)

- `/lab` 페이지와 `lib/lab/video.ts`에 세 방법이 동작하는 상태로 있다(T01).
  - 방법 A: `canvas.captureStream()` + Web Audio → MediaRecorder. 녹음 길이만큼 걸림.
  - 방법 B: Mediabunny(WebCodecs H.264 + AAC). 정지 이미지라 1fps로 만들면 매우 빠름. AAC 인코더가 없는 기기는 `@mediabunny/aac-encoder`(wasm)로 대체.
  - 방법 C: ffmpeg.wasm(참고용, 채택 가능성 낮음).
- 개발 PC 결과와 기기 시험 표 틀: `docs/spike-results.md`
- 참고 앱: https://yetiyagi-madang-cert.vercel.app/ (팀 내 다른 앱. 사진 + 음성 3분 미만은 휴대폰에서 방법 A 방식으로 만들고, 결과가 32MB를 넘으면 공유 창 대신 내려받기로 저장한다. 3분 이상은 서버에서 만든다.)

## 4. 정할 것

1. **방법**: 기본은 방법 B(빠름, 화면을 켜 두고 기다릴 필요 없음), 지원하지 않는 기기는 방법 A로 대체하는 것을 우선 검토한다. 시험 결과로 확정한다.
2. **fps**: 정지 화면이라 1fps면 충분한지, 인스타가 받는지 확인한다(30fps와 비교).
3. **MAX_RECORDING_SEC**: 기사는 170~200단어이고 아이 낭독은 3분을 넘을 수 있다. 아래 시험 기기 전부에서 안정적으로 만들어지는 가장 긴 길이를 찾는다. 3분, 4분, 5분 녹음으로 시험한다.
4. **저장 방식**: 공유 창(`navigator.share`) / 내려받기(`a[download]`) 중 기기별로 무엇을 쓸지, 파일 크기 기준.

| 기기 | 브라우저 환경 | 필수 |
|---|---|---|
| 아이폰 (iOS 최신) | Safari | 필수 |
| 아이폰 | 홈 화면에 추가 후 실행 | 필수 |
| 아이폰 | 카카오톡 채팅방에서 열기 | 필수 |
| 안드로이드 (삼성 갤럭시) | Chrome | 필수 |
| 안드로이드 (삼성 갤럭시) | 삼성 인터넷 | 필수 |
| 안드로이드 | 카카오톡 채팅방에서 열기 | 필수 |
| 아이폰 이전 버전, 안드로이드 보급형 | 기본 브라우저 | 가능하면 |

카카오톡 안에서 안 되면 외부 브라우저 안내로 해결 가능한지 기록한다(안드로이드는 `kakaotalk://web/openExternal` 시험 버튼이 `/lab`에 있다).

## 6. 완료 기준

- 필수 기기 전부에서: 최대 길이 녹음 → MP4 → 사진첩 저장 → 인스타 릴스·게시물에서 선택 → 소리와 화면이 끝까지 정상.
- 만드는 중 화면 꺼짐·앱 전환 시 `BACKGROUNDED`로 끝나고, 다시 시도하면 된다.
- 연결 규칙의 함수가 모두 있고, 1단계 앱이 그대로 불러 쓸 수 있다.
