# T01 기기 기술 검증 (녹음 · 영상 만들기 · 사진첩 저장)

브랜치: `spike/device-media`  
결과물: 실기기에서 열 수 있는 검증 페이지 1개 + 결과 기록  
기한: 개발 1주차 안 (이 결과로 개강일과 영상 처리 방식을 확정한다)

## 1. 왜 하는가

이 앱은 "영상은 서버에 저장하지 않고 휴대폰에서 만든다"를 전제로 설계했다(spec.md 10장).
이 전제가 실제 휴대폰, 특히 아이폰과 카카오톡 안 브라우저에서 성립하는지 먼저 확인한다.
성립하지 않으면 서버에서 영상을 만드는 방식(Cloudflare R2 + 서버 인코딩)으로 바꾸며, 일정이 약 2주 늘어난다.

## 2. 범위

포함
- Next.js 프로젝트 초기 세팅(이후 본 개발에 그대로 쓴다)
- 검증 페이지 `/lab` 하나. 버튼으로 각 검사를 실행하고 결과를 화면에 기록
- Vercel 미리보기 배포(HTTPS. 마이크는 HTTPS에서만 동작)

포함하지 않음
- 로그인, Supabase, 실제 화면 디자인, 서버 업로드
- 검증 페이지는 실험용이다. 코드 품질보다 "어느 기기에서 무엇이 되는지"를 정확히 기록하는 게 목적이다.

## 3. 검증 페이지 구성 (`/lab`)

맨 위: 기기 정보 자동 표시
- userAgent, 플랫폼, 화면 크기, 카카오톡 인앱 여부(UA에 `KAKAOTALK`), 홈 화면 실행 여부(`display-mode: standalone`)
- 기능 지원 여부: `MediaRecorder`, `MediaRecorder.isTypeSupported(...)`(아래 목록), `VideoEncoder`, `AudioEncoder`, `navigator.share`, `navigator.canShare({files})`, `crossOriginIsolated`

이어서 검사 버튼 1~7. 각 검사는 성공/실패, 걸린 시간, 파일 형식·크기, 오류 메시지를 로그에 남긴다.
맨 아래: "결과 복사" 버튼(기기 정보 + 모든 검사 결과를 JSON으로 클립보드에 복사).

## 4. 검사 항목

### 검사 1. 마이크 녹음
- `getUserMedia({audio:true})` → `MediaRecorder`로 녹음 시작/정지, 경과 시간 표시
- 지원되는 mimeType을 순서대로 시도하고 실제 사용한 값을 기록: `audio/mp4`, `audio/webm;codecs=opus`, `audio/webm`
- 녹음 후 `<audio>`로 재생 확인, 길이·크기 기록
- 시험 길이: 10초, 그리고 2분 30초(0.5배 속도로 1주차 지문을 읽는 길이)
- 확인할 것: 권한 창이 뜨는지, "허용 안 함" 후 다시 시도하면 어떻게 되는지, 녹음 중 화면이 꺼지거나 다른 앱으로 갔다 오면 어떻게 되는지

### 검사 2. 기사 이미지 만들기
- `<canvas>` 1080×1350(4:5)에 배경색 #E2F6F3, 기사 제목 "RM Opens His Art Collection to the World", "새벽달 영어뉴스 1주차", 학습자 이름 예시를 그린다
- PNG로 미리보기 표시. 이 이미지를 검사 3의 영상 화면으로 쓴다

### 검사 3. 영상 만들기 (이미지 + 녹음 → MP4)
같은 녹음과 이미지로 세 가지 방법을 각각 시도하고 결과를 비교한다.

- **방법 A: MediaRecorder 실시간 녹화**  
  canvas.captureStream() 영상 트랙 + 녹음 파일을 Web Audio로 재생한 오디오 트랙을 합쳐 MediaRecorder로 녹화.  
  `video/mp4;codecs=avc1,mp4a`(또는 `video/mp4`)를 먼저 시도하고, 안 되면 `video/webm`. 실제 형식을 기록.  
  녹음 길이만큼 시간이 걸리는 방식이다.
- **방법 B: WebCodecs + MP4 컨테이너 라이브러리**  
  `VideoEncoder`(H.264)와 `AudioEncoder`(AAC)로 인코딩하고 MP4로 묶는다. 라이브러리는 Mediabunny 또는 mp4-muxer 중 현재 유지되는 것을 확인해서 쓴다.  
  `AudioEncoder`가 없거나 AAC를 지원하지 않는 기기는 그 사실을 기록한다(실시간보다 빨라야 의미가 있다).
- **방법 C: ffmpeg.wasm (참고용)**  
  단일 스레드 버전으로 이미지 + 오디오 → MP4. 다운로드 용량, 처리 시간, 메모리 오류 여부만 기록한다. 본 개발 채택 가능성은 낮다.

각 방법마다 기록: 성공 여부, 결과 형식(mp4/webm), 코덱, 처리 시간, 파일 크기, 소리와 화면이 끝까지 정상인지.

### 검사 4. 사진첩에 저장
검사 3에서 만든 영상(가장 좋은 방법 결과)으로 두 가지를 시도한다.
- **공유 창**: `navigator.share({files:[mp4File]})` → 아이폰은 "비디오 저장", 안드로이드는 갤러리·파일 저장
- **내려받기 링크**: `<a download>`
- 기록: 공유 창이 뜨는지, 저장 후 사진첩(갤러리)에 실제로 보이는지

### 검사 5. 인스타그램에 올려지는지 (사람이 확인)
- 저장한 영상을 인스타그램 앱에서 게시물(4:5)과 릴스로 각각 골라 본다
- 기록: 목록에 보이는지, 소리가 나오는지, 길이(2분 30초 파일)가 잘리지 않는지
- 실제 게시는 하지 않아도 된다(올리기 직전 화면까지 확인)

### 검사 6. 작성지 사진
- `<input type="file" accept="image/*" capture="environment">`로 촬영
- 촬영한 사진이 사진첩에 자동으로 남는지 기록
- 검사 4와 같은 방법(공유 창)으로 사진첩 저장 시도

### 검사 7. 재생 속도와 하이라이트
- 검사 1의 녹음을 `<audio>`로 재생하며 속도 버튼 0.5 / 0.8 / 1 / 1.2배
- `preservesPitch`(목소리 높이 유지) 동작 여부, 0.5배 음질을 사람이 들어 보고 "괜찮음/어색함" 기록
- `docs/content/week01.md`의 1문단 끊어 읽기 구를, 녹음 길이를 구 개수로 나눈 가짜 시간 정보로 `currentTime`에 맞춰 칠한다. 속도를 바꿔도 맞게 움직이는지 확인

## 5. 시험 기기

| 기기 | 브라우저 환경 | 필수 |
|---|---|---|
| 아이폰 (iOS 최신) | Safari | 필수 |
| 아이폰 | 홈 화면에 추가 후 실행 | 필수 |
| 아이폰 | 카카오톡 채팅방에서 링크 열기 | 필수 |
| 아이폰 (iOS 한 단계 이전 버전) | Safari | 가능하면 |
| 안드로이드 (삼성 갤럭시) | Chrome | 필수 |
| 안드로이드 (삼성 갤럭시) | 삼성 인터넷 | 필수 |
| 안드로이드 | 카카오톡 채팅방에서 링크 열기 | 필수 |
| 안드로이드 (보급형·구형 1대) | Chrome | 가능하면 |

카카오톡 확인 방법: 미리보기 주소를 본인 카카오톡 채팅방(나와의 채팅)에 보내고 눌러서 연다.

추가 확인(안드로이드 카카오톡): 카카오톡에서 외부 브라우저로 여는 스킴(`kakaotalk://web/openExternal?url=…`)이 동작하는지 버튼을 하나 두고 시험한다. 아이폰은 자동 전환 수단이 없으므로 안내 문구가 필요한지만 판단한다.

## 7. 판단 기준 (결론에 반드시 포함)

- **휴대폰에서 영상 만들기 확정**: 필수 기기 전부에서 "녹음 → MP4 → 사진첩 저장 → 인스타에서 선택"이 하나 이상의 방법으로 된다. 카카오톡 안에서 안 되는 것은 외부 브라우저 안내로 해결 가능하면 허용.
- **부분 대응**: 일부 기기만 안 되면 그 기기에서만 서버로 보내 만드는 보조 경로를 제안하고 범위를 추정한다.
- **서버 방식 전환**: 아이폰 Safari 또는 안드로이드 Chrome 중 하나라도 안 되면 서버 인코딩 방식으로 전환을 제안하고, 필요한 구성과 추가 일수를 추정한다.
