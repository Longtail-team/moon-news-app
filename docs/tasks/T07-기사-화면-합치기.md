# T07 기사 화면 합치기·찬반 투표·이해도 평가·활동 카드 (작업지시)

기준: `docs/tasks/T06-뉴스북-청독-앵커.md` 6장(2026-10-10 결정), 시안 `docs/reference/mockup-student-v2.html` "합친 기사 화면"
상태: **작업 전** — PR을 아래 순서대로 작게 나눠 진행

## 1. 목표
청독·기사 읽기·찬반토론을 지문 하나가 있는 기사 화면으로 합치고, 읽기 완료 카드·토론 카드·청독 이해도 평가·찬반 3지선다 투표를 넣는다. 학생 화면은 단순하게 유지한다(운영 데이터는 학생 화면에 넣지 않음).

## 2. 모듈 나누기 원칙
한 파일·한 컴포넌트에 몰아넣지 않는다. 지금 `components/reading/ReadingFlow.tsx`(569줄), `components/work/WorksheetFlow.tsx`(470줄)처럼 커진 파일은 이번 작업에서 나눈다.

- **화면(app/)은 얇게**: 데이터를 불러와 컴포넌트에 넘기기만. 규칙·계산을 넣지 않음
- **DB 호출은 `lib/server/<기능>.ts`**, API는 `app/api/<기능>/…`
- **규칙·계산은 순수 함수로 `lib/<기능>/`** — 화면 없이 단위 테스트
- **브라우저 동작(재생·녹음·카드 그리기)은 훅·모듈로 분리** — 컴포넌트는 그리기만
- **컴포넌트는 약 200줄을 넘으면 나눈다**
- **PR 하나 = 모듈 하나**. 앞 PR이 뒤 PR 없이도 운영에 문제없게(미리보기도 운영 DB를 쓰므로 DB 변경은 기존 화면과 호환)
