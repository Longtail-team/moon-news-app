# T06 뉴스북·청독·이달의 앵커 (2026-10-09)

뉴스북 PDF 구성안(2026-10-09 확정본)과 그 뒤 논의로 정한 기능. 이 문서는 작업 범위, 결정, 남은 이슈를 한곳에 모은다.
제품 규칙은 `docs/spec.md`(6·7·8·9·17장), 날짜별 경과는 `docs/devlog.md`.

## 1. 목표

12주 동안 학생이 한 일을 "내 영어 뉴스북"으로 모아 주고, 매일 하기 쉬운 청독 미션과 낭독 도전(이달의 앵커)으로 주 5회 완주를 돕는다.

## 3. 결정 (2026-10-09)

뉴스북
- 기수별 1권(12주). 하단 네 번째 탭 "내 기록"에서 학습자별로 본다. 진도 중간에는 화면 열람, 종강 다음 날(KST 0시)부터 PDF 다운로드
- 구성: 표지 → 이번 기수의 기록 → 기사별 쪽(뉴스 카드·의견 카드·찬반 결과·청독 카드 4열) → 내가 붙인 제목. AI 한 줄 피드백은 제외
- 보상 PDF(12주 기사·VOCA 모음)는 뺀다. 뉴스북이 보상

기자수첩·의견
- 요약 제목·텍스트, 입장·이유 모두 선택 입력. 학습 완료 조건(작성지 사진 1장)은 그대로
- 사진 글자 읽기: 외부 AI(Claude Haiku 5.5, 활동마다 3번), 읽은 글자를 보여 주고 "수정하실래요? 이대로 저장하실래요?". 첫 접속 3단계의 선택 동의를 한 학습자만
- 찬반 투표: 주차별 기사, 그 주 일요일 자정 마감, 마감 뒤 의견은 저장하지 않음. 고른 학생에게만 결과를 바로 보여 줌
- 보관: 사진과 같이 종강 후 3개월

청독
- 영어 기사 음원·한영 구간반복을 90% 이상 들으면 "청독 완료" → 학습 1회. 청독만으로 완주 인정
- 기사 음원은 청독에서만 듣는다(기사 읽기 화면은 청독 링크). VOCA 구간반복은 문장이 아니라 청독이 아니며 VOCA 탭에 둔다
- 청독량 = 실제 재생 시간(반복·배속 반영). 청독 화면 + 이번 주 자료
- 청독 카드: 기사 스크랩 + 도장(시안 C). 인스타용(제목 100px, 청독 완료 화면·인스타 올리기에서 저장)과 앱·뉴스북용(제목 68/58px). 도장은 카드마다 자리·각도가 다르고 살짝 겹쳐도 됨
- 청독 화면에 지문과 청독 하이라이트(영어 음원은 끊어 읽기 구, 한영은 한국어 → 영어 2회)

이달의 앵커
- 4주 묶음(1~4, 5~8, 9~12주차). 후보 = 주간 목표 3주 이상 달성 + 영어 낭독 제출 3회 이상, 둘 다 (숫자는 설정값, 바뀔 수 있음)
- 출품: 후보가 그 4주의 영어 낭독 하나를 고르고 보호자 공개 동의(필수)

완주·상장
- 완주 화면: COMPLETE!(제때만), 인증 수, 활동별 횟수, 읽은 영어 단어, 청독 시간, 첫·마지막 낭독(제때·유예만), 뉴스북, 상장
- 상장 PDF: 서버에서 만들어 휴대폰에서 받기, 발급 기관 "새벽달"(임시), 디자인은 차차 보완

## 4. 남은 이슈 (회의·결정 필요)

1. 이달의 앵커: 수상작 수와 선정 방법(관리자 화면 전에는 운영팀 요청 → 개발 담당이 표시), 수상작 화면의 이름 표시(전체 / 부르는 이름 / 가림), 다른 아이 음성 공개 동의 문구(법률 검토)
2. 지난 기수 학습 기능 잠금 시점: 종강 직후 / 유예 후 / 올리기 마감(종강 후 30일)과 같이
3. 뉴스북: 기록 없는 주차를 PDF에서 뺄지(지금은 뺌), 한 주 여러 요약 중 마지막만 싣는 기준
4. 첫 낭독을 마지막 낭독 뒤에 공개하는 순서(지금은 둘 다 바로 보임)
5. 사진 글자 읽기 모델 정확도: 수강생 제출이 쌓인 뒤 판단, 부족하면 `OCR_MODEL` 교체
6. 보호자 동의 문구 법률 검토(사진 외부 AI 전송, 음성 수집)
7. 완주 알림톡·상장 알림톡: 솔라피 연결 전이라 기록만
8. 상장 디자인(제때·유예·늦은 완주 차이 포함)
9. 개발용 Supabase 프로젝트: 지금은 미리보기도 운영 DB를 써서, DB 변경은 미리보기 전에 운영 DB에 먼저 반영됨
10. 콘텐츠: 1기 시트 2주차 한국어 해석, 단어·추가 자료·라이브 탭, 음원·PDF 파일 업로드 후 반영

## 6. 기사 화면 합치기·찬반 투표·청독 평가 기획 (2026-10-10)

순서: 회의용 시안 먼저 → 회의 확인 → 앱 구현. 시안은 `docs/reference/mockup-student-v2.html` 왼쪽 목록 "합친 기사 화면 (10월 10일 안)", 지금 앱은 "지금 앱 · 탭별 화면 (비교용)".

방향 (요청)
- **합친 기사 화면**: 청독·한국어/영어 기사 읽기·찬반토론이 같은 지문을 쓰므로 지문은 한 화면에 한 번. 아래 시트에서 청독 / 기사 읽기 / 찬반토론을 바꾼다. 학습 고르기·12주 기록 빈칸에서는 지금처럼 활동별로 들어오되 그 시트가 열린 채로. 학습 1회 세는 법은 그대로
  - 청독 시트: 음원 고르기(영어 기사·한영 구간반복), 재생·진행, 속도, 반복, 이번 청독 시간, 90% → 청독 완료
  - 기사 읽기 시트: 한국어로 / 영어로 → 읽기 시작(3초 뒤 녹음, 시트가 녹음 막대로 줄고 다른 활동 잠금) → 내 낭독 듣기 + "읽기를 완료했어요 / 다시 읽을게요"
  - 지문 위 영어 / 한·영 / 한국어 전환(시트에 맞춰 자동, 직접 바꿀 수 있음)
  - (10-10 피드백) 화면 합치기가 나아 보임 → 위쪽 요소 줄이기. 기사 PDF 받기는 뺌(이번 주 자료 탭에 있음). 듣기 전 질문은 "이 질문을 생각하며 들어/읽어 봐요"로 들어올 때 펼쳐 두고, 재생·읽기를 시작하면 한 줄로 접힘(누르면 다시 펼침). 질문이 청독·낭독 집중이라는 의도대로 작동하는지는 회의 질문 8
  - (10-10 피드백 2) 지문 상자의 "기사" 글자 뺌. 상자 위 한 줄에 왼쪽 영어 / 한·영 / 한국어(보이는 칸 30px로 작게, 눌리는 영역은 44px 유지), 오른쪽 끊어 읽기
- **읽기 완료 카드**: 청독 카드와 같은 모양 + "낭독" 도장. 영어는 오늘 읽은 단어·누적 단어, 한국어는 읽은 시간·낭독 횟수. 영상 = 카드 + 녹음, "영상 저장" 때 휴대폰에서 만듦
- **찬반토론**: 작성지 받기·사진 올리기를 빼고 지문 아래에 토론 질문(임시, 나중에 콘텐츠 시트 기사 탭에서). 찬성해요 / 반대해요 / 잘 모르겠어요를 누르면 버튼마다 비율이 바로 보임. 이유 한 줄(시안 80자) → 학습 1회. "다른 친구들의 생각" 전체 / 찬성 / 반대 / 잘 모르겠어요 거르기(고른 뒤에만 보임, 이름 안 보임)
- **토론 카드(인스타용, 10-10 결정)**: 입장·이유·투표는 앱과 뉴스북에만 저장하고, 인스타 카드에는 개인 의견을 넣지 않음(공개 여부를 아이에게 맡기지 않음). 의견 내기 직후 "오늘 토론 주제는 어땠어요?" 반응 4가지 중 하나(첫 토론 필수, 정답 없는 반응형 — 문구 임시: 더 이야기하고 싶어요 / 재미있었어요 / 그저 그랬어요 / 어려웠어요). 카드 = 청독·읽기 카드와 같은 모양 + "토론" 도장, 토론 질문, "N명이 함께 토론했어요" + 찬성/반대/잘 모르겠어요 비율(날짜 기준, 익명 집계), 내 반응. 반응은 운영 시트·대시보드에서 기사별 토론 주제 반응으로 집계
- **청독 이해도 5단계**: 청독 완료 직후. 같은 기사 첫 청독은 필수, 다시 청독은 선택(건너뛰기). 점수는 DB → 운영 시트로 내보내 기사별·학년별·학습자별 난이도와 변화를 집계, 관리자 대시보드에서도 봄. 단계 기준(10-10 확정, 1·2단계 차이가 흐려 "무엇까지 알아들었나"로 다시 씀): 1 한국어 해석을 보면 무슨 내용인지 알 수 있어요(영어로만 들을 때는 아직 어려웠어요 — "거의 못 알아들었어요"는 고르고 싶지 않은 말이라 바꿈) / 2 아는 단어만 들렸어요(단어는 들리는데 무슨 이야기인지는 잘 모르겠어요) / 3 무엇에 대한 기사인지 알겠어요(주제는 알지만 자세한 내용은 많이 놓쳤어요) / 4 내용을 대부분 이해했어요(몇 군데만 놓쳤어요) / 5 친구에게 설명할 수 있어요(한국어 해석 없이도 거의 다 이해했어요)
- **관리자 대시보드**: 초기 양식(목록·상세 화면)을 받음. 운영 시트와 연동하고 학습자별 난이도·평가를 집계(spec 14장)
