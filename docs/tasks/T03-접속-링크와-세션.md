# T03 접속 링크와 세션 (개발 1단계)

브랜치: `feat/access-link`  
기준 문서: spec.md 3장(사용자와 계정), 11장(첫 접속과 다시 들어가기), 12장(알림톡 받는 사람), 16장(access_tokens)  
상태: **설계안. 아래 "결정 필요"가 정해지면 구현한다.**

## 1. 하는 일

로그인 화면 없이, 알림톡으로 받은 개인 링크를 누르면 바로 들어오고, 한 번 들어온 브라우저는 다음부터 링크 없이 열리게 한다.
이후 모든 화면(첫 접속 3단계, 홈, 활동, 인스타 올리기)은 이 작업이 만든 "지금 누가 접속했는지"를 쓴다.

## 2. 비유로 본 구조

- **접속 링크 = 열쇠.** 알림톡으로 받는 주소 `news.momthereader.com/a/<무작위 문자열>`. 서버에는 원문이 아니라 해시만 저장한다(이미 T02에 반영).
- **세션 = 출입증.** 열쇠로 한 번 문을 열면 브라우저에 출입증(쿠키)을 붙여 준다. 다음부터는 출입증만으로 들어온다.
- **다시 들어가기 = 열쇠 재발급.** 출입증도 열쇠도 없을 때 등록된 번호로 새 열쇠(또는 인증번호)를 받는다.

## 3. 흐름

### 3-1. 처음 들어오기
1. 아임웹 결제 → 보호자 번호로 "시작 안내" 알림톡(링크 포함)
2. 링크를 누름 → 서버가 링크 확인(해시 비교, 폐기·만료 여부)
3. 서버가 세션을 만들고 쿠키를 붙인 뒤, 주소창에서 링크 문자열을 지운 주소(`/`)로 보낸다(주소가 기록·공유되어 새지 않도록)
4. 처음이면 첫 접속 3단계(T04), 아니면 홈

### 3-2. 다음부터
- 같은 브라우저면 링크 없이 `news.momthereader.com`만 열어도 홈으로 들어온다.
- **주의: 브라우저마다 출입증이 따로다.** 카카오톡 안 브라우저, Safari·Chrome, 아이폰 "홈 화면에 추가" 앱은 쿠키를 서로 나누지 않는다(아이폰 홈 화면 앱은 실기기 확인 필요). 그래서 같은 링크를 다른 브라우저에서 다시 눌러도 들어올 수 있어야 한다 → **링크는 여러 번 쓸 수 있게** 한다(결정 1).

### 3-3. 보호자·자녀·형제
- 보호자 링크로 들어오면 **그 보호자의 자녀 전부**를 볼 수 있고, 형제가 있으면 프로필을 고른다.
- 자녀 링크로 들어오면 **그 자녀 한 명만** 본다. 형제 기록은 보이지 않는다.
- 이 범위가 세션에 담겨 DB 권한(RLS: `student_ids`, `guardian_id`)으로 그대로 이어진다(T02에 반영).

### 3-4. 다시 들어가기
1. 첫 화면의 "다시 들어가기"에서 휴대폰 번호 입력
2. 등록된 번호(보호자 번호 또는 자녀 본인 번호)면 알림톡 발송. 등록되지 않은 번호여도 **같은 안내**를 보여 준다("등록된 번호라면 알림톡을 보냈어요"). 번호 등록 여부를 드러내지 않기 위해서다.
3. 받는 방식은 결정 3.
4. 같은 번호·같은 기기에서 짧은 시간에 반복 요청하면 막는다(알림톡 비용·도배 방지).

### 3-5. 막히는 경우
- 환불 완료(approved): 링크와 세션을 모두 폐기한다. 재수강의 지난 기수가 남아 있으면 링크를 유지하고 환불한 기수 페이지만 가린다(2026-10-07 결정, T02에 반영).
- 관리자 "접속 링크 재발급"(spec 14장): 새 링크를 보내고, 이전 링크를 폐기할지는 결정 2.

## 4. 결정 필요

### 결정 1. 링크를 몇 번, 언제까지 쓸 수 있게 할까
- **추천: 여러 번 사용 가능, 종강 후 3개월(녹음 보관 기간 끝)까지 유효.**
  - 이유: 카카오톡 안 브라우저 → Chrome/Safari로 옮겨 열기, 기기 바꾸기, 홈 화면 앱 등 같은 링크를 다시 누를 일이 많다. 한 번만 쓰는 링크면 이때마다 "다시 들어가기"를 거쳐야 한다.
  - 대가: 링크가 전달되면 받은 사람도 들어올 수 있다. 알림톡은 본인 번호로만 가므로 위험은 낮다고 본다.
- 다른 안: 한 번만 사용(보안은 높지만 위 불편이 크다).

### 결정 2. 새 링크를 보내면 이전 링크는?
- **추천: 이전 링크는 그대로 둔다.** 이미 들어와 있는 기기(세션)도 유지한다.
- 예외: 관리자가 "유출·번호 변경" 사유로 재발급할 때만 이전 링크와 세션을 함께 폐기하는 버튼을 따로 둔다.

### 결정 3. "다시 들어가기"로 받는 것: 새 링크 vs 인증번호
- spec 11장은 "새 링크를 알림톡으로", 19장 일정은 "다시 들어가기 인증번호"로 서로 다르게 적혀 있다.
- **추천: 인증번호(6자리, 10분 유효, 5회 틀리면 무효).**
  - 이유: 아이폰 홈 화면 앱 안에서 다시 들어가려 할 때, 알림톡의 링크를 누르면 홈 화면 앱이 아니라 카카오톡이나 Safari가 열려서 홈 화면 앱은 계속 로그인되지 않는다. 인증번호는 지금 보고 있는 화면에 그대로 입력하므로 어디서든 된다.
  - 링크도 함께 넣어 둘 수 있다(번호 입력이 어려운 경우용).

### 결정 4. 출입증(세션) 유지 기간
- **추천: 마지막 사용 후 180일**(쓸 때마다 연장). 종강 후 3개월 보관 기간 동안 완주 화면·상장 수정에 들어올 수 있어야 하므로 기수 기간보다 길게 둔다.
- 기기 수 제한 없음(보호자 폰 + 자녀 태블릿 등).

### 결정 5. 결제 직후 아직 학습자가 없을 때의 데이터 (데이터 모델 변경 제안)

| 구분 | 내용 |
|---|---|
| 기존안 | 접속 링크(access_tokens)와 수강(enrollments)이 학습자(student_id)에 붙어 있다 |
| 문제 | 시작 안내 링크는 결제 직후, 학습자 등록(첫 접속 2단계) **전에** 보낸다. 이 시점엔 학습자가 없어 링크와 수강을 만들 수 없다 |
| 변경안 | 보호자 링크는 보호자(guardian_id)에 붙인다(`access_tokens.guardian_id` 추가, 보호자 링크는 student_id 없음). 수강은 결제 시점에 보호자 기준으로 만들고 학습자는 등록 때 채운다(`enrollments.guardian_id` 추가, `student_id`는 등록 전까지 비어 있을 수 있음) |
| 이유 | 결제 → 링크 → 등록 순서를 그대로 지원. 보호자 링크 하나로 형제 프로필을 모두 고를 수 있다(spec 3장) |
| 영향 범위 | T02 테이블·집계·RLS·테스트 일부 수정. 집계는 학습자가 등록된 수강만 센다 |

- 함께 확인할 것: **형제를 한 번에 결제하면 아임웹 주문이 1건(수량 2)인지 2건인지.** 수강 기록을 몇 개 만들지가 여기서 정해진다.

### 결정 6. 세션 구현 방식 (기술)
- **추천: 브라우저는 우리 서버(Next.js)하고만 통신하고, Supabase에는 서버가 접속한다.**
  - 출입증 쿠키: 무작위 값, 서버에는 해시만 저장(`sessions` 테이블 추가), 자바스크립트로 읽을 수 없는 쿠키(httpOnly, Secure).
  - 서버가 요청마다 그 세션의 범위(`student_ids`, `guardian_id`)를 담은 짧은 Supabase 토큰을 만들어 DB에 접근 → T02의 RLS가 2중 안전장치가 된다.
  - Supabase의 토큰 서명 키 방식(새 비대칭 키)에서 직접 토큰을 만드는 방법은 구현 전에 공식 문서로 확인한다.
- 관리자 대시보드 로그인은 이 작업에 포함하지 않는다(운영팀 계정 방식, 별도 작업).

## 5. 범위 (결정 후 구현)

- 링크 열기 `/a/<토큰>`: 확인 → 세션 발급 → 링크 문자열 없는 주소로 이동
- 세션 확인(모든 화면 공통), 보호자 형제 프로필 고르기 화면(최소)
- 다시 들어가기: 번호 입력 → (인증번호 입력) → 세션 발급, 요청 횟수 제한
- 링크·인증번호 발송은 알림톡 모듈 인터페이스로만 호출. 솔라피 연결 전에는 개발용 발송기(서버 기록에만 남김)로 시험
- `sessions` 테이블, (결정 5 승인 시) access_tokens·enrollments 변경 마이그레이션과 테스트
- 링크·토큰·인증번호를 로그와 주소창에 남기지 않는다. 링크 페이지는 `Referrer-Policy: no-referrer`
- 카카오톡 안에서 열렸을 때 외부 브라우저로 넘기는 경우(안드로이드), 링크를 함께 넘겨 그쪽에서도 들어오게 한다

## 6. 미리 해 둘 일 (사람)

- **알림톡 템플릿 카카오 사전 승인**: 시작 안내, 자녀 접속 링크, 다시 들어가기(인증번호 또는 새 링크). 승인에 시간이 걸리므로 문구를 먼저 정해 신청한다.
- 솔라피 계정·발신 프로필 준비.

## 7. 완료 기준

- 보호자 링크 → 첫 접속 → 다음부터 링크 없이 홈. 자녀 링크 → 자녀 한 명만 보임. 형제 보호자 → 프로필 고르기.
- 카카오톡 안 브라우저, Safari·Chrome, 아이폰 홈 화면 앱에서 각각 들어오기와 다시 들어가기.
- 환불 완료 시 링크·세션 폐기, 재수강 지난 기수 유지.
- 등록되지 않은 번호로 다시 들어가기 → 등록된 번호와 같은 안내, 발송 없음.
- 위 규칙의 자동 테스트.
