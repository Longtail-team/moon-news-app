# T04 첫 접속 3단계와 다시 들어가기 (개발 1단계)

브랜치: `feat/first-access`  
기준: spec.md 3장(사용자와 계정), 11장(첫 접속, 2026-10-08 접속 방식 결정), 12장(받는 사람), 16장(orders, access_tokens)

## 1. 흐름
1. 아임웹 결제 → 주문 기록(orders: 결제자 번호, 기수, 수량) → 보호자 링크 발급 → 결제 완료·시작 안내 알림톡
2. 링크(외부 브라우저) → `/?k=<링크>`에서 세션 → 첫 접속 3단계(끝나지 않았으면 홈 대신)
   - 1 환영: 신청 정보·제공 자료 확인, 보호자 이름, 알림톡 수신 동의, 홈 화면 추가 안내
   - 2 학습자 등록: 주문 수량만큼(형제). 이름, 출생 연월(학년 자동, 바꾸기 가능), 인스타 ID. 재수강생은 지난 기수 학습자 고르기
   - 3 접속 방법과 동의: 학습자마다 본인 휴대폰 여부(예면 자녀 번호 → 자녀 링크 알림톡), 음성·이미지 수집 보호자 동의
3. 홈 화면에 추가하면 아이콘이 `/?k=<링크>`를 품는다 → 세션이 없으면 그 링크로 다시 세션
4. 다시 들어가기: 번호 입력 → 등록된 보호자·자녀 번호면 새 링크 알림톡. 결과와 상관없이 같은 안내. 같은 번호는 1시간 3회까지

## 2. 이번 범위에 없는 것
- 아임웹 결제 신호 받기(API·웹훅 확인 필요) → 시험용 주문 만들기 스크립트(`scripts/test-order.mjs`)로 대신
- 솔라피 실제 발송(계정·발신 프로필·템플릿 승인 필요) → 발송은 기록만 남기고, 미리보기에서는 보낼 링크를 화면에 보여 준다(`DEV_OUTBOX=1`, Preview 환경에만)

## 3. 완료 기준
- 시험 주문(형제 2명) 링크 → 3단계 → 홈, 형제 프로필 고르기
- 홈 화면 추가용 주소(`/?k=`)로 세션 없이 열어도 들어옴
- 자녀 링크로 자녀 한 명만 보임
- 다시 들어가기: 등록 번호·미등록 번호 같은 안내, 반복 요청 제한
- 환불 시 링크 폐기 규칙이 보호자 링크에도 맞게 동작(다른 자녀·남은 자리가 있으면 유지)
- DB 테스트
