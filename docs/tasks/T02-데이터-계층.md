# T02 데이터 계층 (T01 결과 확정 후 시작)

브랜치: `feat/data-layer`

화면은 아직 만들지 않는다. 기준 문서는 `docs/spec.md` 16장(데이터 명세)과 12장(알림톡), 5장(완주)이다.
규칙을 짐작해서 채우지 말고, 문서에 없는 결정이 필요하면 멈추고 질문 목록으로 남긴다.

1. Supabase 마이그레이션
   - 회원·수강·기록 테이블 9개와 학습 자료 테이블 5개(spec.md 16장. 문장 단위 `sentences`, 음원 시간 정보 `timing_key` 포함)
   - 외래 키, 인덱스(activities의 enrollment_id + week_no, verified_at 여부)
   - 권한 규칙(RLS): 학습자는 자기 기록만, 보호자는 자기 자녀 기록만
   - 환불 시 access_tokens 자동 폐기
2. 집계 뷰 (횟수는 저장하지 말고 계산)
   - 학습자별: 이번 주 학습, 누적 학습, 인증 수, 올릴 것 개수, 완주 단계, 누적 낭독 단어 수
   - 관리자 목록용: 학습 밀림, 게시 밀림, 진도 독려 받은 회차
   - 진도 독려 대상 판정(2·4·7주차 월요일, 학습 완료 기준 밀린 양), 알림 받는 사람 결정(보호자·자녀)
3. 샘플 데이터
   - 1기, 12주, 1주차는 `docs/content/week01.md`, 나머지 11주는 자리표시 텍스트, 학습자 8명
   - 정상, 학습 밀림, 게시 밀림, 미시작, 형제 수강, 자녀 본인 접속, 환불, 재수강, 늦은 완주 사례 포함
4. 검증
   - 샘플 데이터로 집계 결과가 문서 규칙과 맞는지 확인하는 테스트
   - 결과와 남은 질문을 PR 설명에 정리

파일 저장소 접근 코드는 한 모듈에 모아, T01 결과에 따라 Supabase Storage에서 R2로 바꿀 수 있게 한다.
