## 안드로이드 1차 시도 (참고)

갤럭시(SM-S942N, Android 16)에서 열었으나 **네이버 앱 인앱 브라우저**(웹뷰)였고, 페이지가 다시 열리며 자동 기록이 사라져 결과로 쓰지 않는다.
기기 정보로 확인된 것: MediaRecorder, `video/mp4`(avc1 + mp4a), VideoEncoder·AudioEncoder(H.264·AAC), 공유 창(mp4 파일 공유 가능) 모두 지원.
이후 `/lab`이 기록을 브라우저에 저장하고 접속 환경을 맨 위에 표시하도록 고쳤다.

## 결론 (2026-10-07)

- **휴대폰에서 영상 만들기로 간다. 서버 합성(R2)은 도입하지 않는다.**
  - 근거: 개발 PC에서 방법 A·B·C 모두 동작, 갤럭시 기기 정보상 필요한 기능 모두 지원, 팀 내 다른 앱(https://yetiyagi-madang-cert.vercel.app/)이 3분 미만 사진 + 음성을 휴대폰에서 방법 A 방식으로 만들어 운영 중.
- 실기기 전체 시험은 **개발 2단계(영상 합성 모듈, `docs/tasks/V01-영상-합성-모듈.md`)**로 넘긴다. 개발은 1단계(영상 합성 외 전부)와 2단계로 나누고, 출시는 한 번 한다.
- 아이폰 Safari 또는 안드로이드 Chrome에서 2단계 시험이 실패하면 그때 서버 합성을 다시 검토한다(T01 7장 기준).

## 본 개발에 반영할 것

- 녹음 형식: 기기가 고르는 형식 그대로 저장(`audio/mp4` 우선, 안 되면 `audio/webm;codecs=opus`). 영상 모듈 입력이 된다.
- 녹음 최대 길이: 휴대폰 합성이 안정적인 길이(V01에서 확정). 1단계는 설정값 하나로 읽고 남은 시간 안내 + 자동 정지.
- 영상 형식·해상도: MP4(H.264 + AAC), 1080×1350. 방법과 fps는 V01에서 확정.
- 영상 이미지: 운영자가 만든 주차별 인스타 템플릿 이미지(`assets.type` 추가).
- 저장 방식: 공유 창 우선, 안 되거나 파일이 크면 내려받기(V01에서 확정).
- 카카오톡 안내: V01 기기 시험 후 결정.
