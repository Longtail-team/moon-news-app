# 낭독 챌린지 컨텍스트 및 작업지시서 (통합본)

최종 갱신 2026년 10월 9일

> 이 문서는 팀 공유 Claude와 Claude Code가 제품 맥락을 유지하며 UX·데이터·기술 설계를 이어가기 위한 **유일한 기준 문서**다. 이전 버전(v1)과 결정 기록(v2)을 하나로 합쳤으며, 이전 문서는 더 이상 참조하지 않는다. 결정이 바뀌면 이 문서를 고친다.


## 1. 제품 정의

초등 4~6학년 및 중학생을 대상으로, 12주 동안 매주 하나의 영어 기사를 깊게 학습하고 낭독·VOCA·요약·찬반토론 중 원하는 활동을 반복 선택하여 인스타그램으로 인증하는 유료 챌린지형 웹앱. 보호자와 자녀가 함께 사용한다.


## 2. 사업·운영 맥락

- 대상: 엄마표 영어의 기반이 약하거나 원서 읽기를 놓친 초등 4~6학년 및 중학생.
- 기간·가격: 12주(3개월), 12만 원. 기수제로 반복 운영한다.
- 규모: 기수당 200~300명, 최대 500명을 설계 기준으로 한다. 500명 × 60회 = 기수당 학습 기록 최대 30,000건.
- 매주 1개의 기사에 집중한다.
- PDF 2종: ① 기사 PDF(기사 원문 한영시트 + 기사 요약 작성지 + 찬반토론 질문·작성지를 한 파일로 묶음) ② VOCA 정리 PDF. 요약 작성지와 토론 질문지는 매주 같은 양식이다.
- 음원: ① 영어 기사 AI 음원 ② 새벽달 한영 구간반복 음원(한국어-영어 2회) ③ VOCA 구간반복 음원(한국어-영어 3회).
- 새벽달 Zoom Live: 12주 동안 2회, 이후 기수는 1회로 줄일 예정.


## 3. 사용자와 계정

- 등록은 항상 결제한 보호자 연락처로 시작한다. 보호자 계정 아래에 학습자(자녀) 프로필을 둔다.
- 자녀가 본인 휴대폰으로 진행하면 자녀 연락처를 입력받아 자녀에게 별도 접속 링크를 보낸다. 보호자와 자녀는 같은 학습 기록에 접근한다.
- 형제 수강은 보호자 한 명 아래 학습자 프로필 여러 개로 처리하고, 접속 시 프로필을 고른다.
- 인스타그램 ID는 학습자마다 하나를 연결한다. 보호자 계정이든 자녀 계정이든 무방하다.
- 학습자 나이는 학년 대신 **출생 연월**로 받는다. 학년은 자동 계산하고, 만 14세 미만 여부(보호자 동의 필요 여부)를 판단하는 데 쓴다. 생년월일 전체는 받지 않는다.
- 내부 식별자는 전화번호가 아닌 변하지 않는 student_id를 쓴다. 전화번호는 연락과 조회용이다.
- 재수강 시 새 회원을 만들지 않고 기존 학습자에 수강 기록(enrollment)을 추가한다.


## 4. 추천 루틴과 실제 진도


### 추천 루틴

| 요일 | 추천 활동 |
| --- | --- |
| 월 | 한국어 기사 읽기 |
| 화 | VOCA 공부 |
| 수 | 기사 요약 글쓰기 |
| 목 | 찬반토론 글쓰기 |
| 금 | 영어 기사 읽기 |

위 표는 학습 가이드일 뿐 체크리스트나 출석 판정 기준이 아니다. 활동 선택 화면에서 "오늘 추천"으로만 표시한다.


### 실제 진도 규칙

- 주간 목표 5회, 12주 총 60회.
- 활동 종류와 순서는 자유이며 같은 활동 반복을 허용한다. 반복해도 매번 1회로 인정한다.
- 하루 인증 횟수에 상한은 없다. 주말에 몰아서 하는 가정을 허용한다.
- **학습 완료와 인스타그램 인증을 분리해 센다.** 주간 진도는 학습 완료 기준, 완주 진행률은 인스타그램 인증 기준이다.
- 주간 학습 = 해당 주차의 학습 완료 건수 ÷ 5. 완주 진행률 = 인스타그램 인증 건수 ÷ 60.
- 학습 완료 후 인증하지 않은 기록은 "올릴 것"으로 표시한다(데이터·관리자 용어는 게시 대기).
- 모든 주차는 닫히지 않는다. 지난 주차도 언제든(종강 후 포함) 소급해서 채울 수 있다. 실적은 학습자가 고른 주차에 귀속한다(2026-10-07 확정). 아직 시작하지 않은 주차는 고를 수 없다.
- 종강일은 주차 귀속이 아니라 완주 단계 판정에만 쓴다: 60번째 인증 시각이 종강일(KST) 안이면 제때, 유예 기간 안이면 유예, 그 뒤면 늦은 완주.
- 활동 다양성은 기록하되 성취도 점수로 사용하지 않는다.


## 5. 완주와 마감

- 완주 기준은 **인스타그램 인증 60회**다.
- 제때 완주 마감은 12주차 마지막 일요일이다. 학습뿐 아니라 인증 60회까지 이날 끝나야 한다. 진도대로 완주하는 것을 권장하는 취지다.
- 마감 후 1주(유예) 안에 완주하면 낭독 비교까지 받는다. 그 이후에도 완주는 기한 없이 허용한다.
- 학생에게 보이는 마감일은 12주차 일요일 하나이며, 화면에서는 "종강일"로 부른다. 유예는 미리 알리지 않고, 마감을 넘긴 학습자에게만 앱 홈에서 안내한다.

| 완주 시점 | 상장 | 첫·마지막 낭독 비교 | COMPLETE! 뱃지 |
| --- | --- | --- | --- |
| 12주차 일요일까지 (제때) | 이름 확인 후 발급 | 있음 | 있음 |
| 마감 후 1주 이내 (유예) | 이름 확인 후 발급 | 있음 | 없음 |
| 그 이후 (기한 없음, 늦은 완주) | 이름 확인 후 발급 | 없음 | 없음 |

- ~~보상 PDF~~(12주 기사·VOCA 모음): **빼기로 함(2026-10-09)**. 주차별 자료를 매주 받을 수 있고, 기수별 뉴스북(내 기록 탭, 종강 다음 날부터 PDF)이 더 큰 보상이다. 완주 화면에도 두지 않는다.
- 상장 PDF는 디자인한 양식으로 서버에서 만들어 휴대폰에서 받는다. 발급 기관 표기는 "새벽달"(임시).
- COMPLETE! 뱃지는 학생 완주 화면과 관리자 대시보드에 표시한다. 진행 중에는 미리 안내하지 않는다.


### 완주 상장

- 상장에는 학습자 이름(학습자 등록 화면에서 입력), 과정 이름과 기수, 기간, 완주일이 들어간다. 이름은 한국어로만 쓴다.
- 학습자 등록 화면에서 "완주 상장에 이 이름이 그대로 들어가요. 성과 이름을 모두 써 주세요"라고 안내한다.
- "완주 상장 받기"를 누르면 이름 확인 화면이 먼저 나온다. 상장 미리보기와 이름 칸을 보여주고, "이 이름으로 상장 받기"를 눌러야 발급된다.
- 발급 후에도 학습자가 완주 화면에서 이름을 고칠 수 있다. 고칠 때마다 새 상장을 발급해 다시 보낸다. 운영팀 요청은 필요 없다.
- 발급할 때 쓴 이름은 enrollments.certificate_name에 따로 저장한다. 발급할 때마다 알림 기록(notifications)에 남는다.


## 6. 핵심 UX 모델: Week → Activity Record → Step State

화면과 데이터 모두 요일이 아니라 "주차 + 자유 활동 + 작업 상태"를 중심으로 설계한다.


### 활동 유형과 완료 기준

| 코드 | 활동 | 학습 완료 조건 | 인스타그램 게시물 |
| --- | --- | --- | --- |
| KR_READING | 한국어 기사 읽기 | 녹음 후 '이대로 완료' | 이미지 + 음성 영상 |
| EN_READING | 영어 기사 읽기 | 녹음 후 '이대로 완료' | 이미지 + 음성 영상 |
| VOCA | VOCA | 단어 낭독 녹음 또는 작성지 사진 1장 | 영상 또는 사진 |
| SUMMARY | 기사 요약 | 작성지 사진 1장 | 사진 |
| DEBATE | 찬반토론 | 작성지 사진 1장 | 사진 |


### 활동 상태

NOT_STARTED → STARTED → RECORDED 또는 CONTENT_READY → COMPLETED(학습 완료) → VERIFIED(인스타그램 인증)

**기자수첩과 의견 (2026-10-09, 뉴스북 구성안)**: 모두 선택 입력이며 학습 완료 조건은 그대로(작성지 사진 1장)다.
- 기사 요약: "내가 붙인 제목"과 요약 텍스트. 사진에서 글자 읽기(외부 AI, 활동마다 3번까지)를 누르면 읽은 글자를 보여 주고 "수정하실래요? 이대로 저장하실래요?"로 고르게 한다. 이대로 저장하면 바로 저장, 수정하면 고친 뒤 완료할 때 저장. 모델은 가장 싼 Claude Haiku 5.5로 시작하고, 정확도는 수강생 제출이 쌓인 뒤 판단한다(2026-10-09).
- 찬반토론: 입장(찬성/반대)과 이유 한 문장. 그 주차 일요일 자정(주차 끝)까지만 받고, 마감 뒤에는 저장하지 않는다(주차 안에 완주하도록 유도). 찬반토론 활동(사진)은 지난 주차도 소급할 수 있다.
- 의견은 고르는 순간 저장하고, **고른 학생에게만 그때까지의 찬반 결과를 바로 보여 준다. 고르기 전에는 볼 수 없다**(2026-10-09). 마감 뒤에는 그 주차에 의견을 골랐던 학생에게만 최종 결과를 보여 준다.
- 찬반 비율 = 그 기수·주차에서 마감 전에 저장된 의견, 학습자마다 마지막 1개("고르지 않음"으로 바꾸면 빠짐). 마감 뒤에는 저장하지 않으므로 마감 시점에 고정된다. 뉴스북에도 싣는다.
- 요약 텍스트·의견은 사진과 같이 종강 후 3개월에 지운다.
- 사진에서 글자 읽기(외부 AI 전송)는 첫 접속 3단계의 **선택 동의**("작성지 사진의 손글씨를 글자로 읽기 위해 사진을 외부 AI 서비스(Anthropic)로 보내는 데 동의합니다")를 한 학습자만 쓴다. 동의하지 않으면 버튼을 쓰지 않고 요약은 직접 입력하며, 학습·완주에는 영향이 없다. 나중에 바꾸는 화면은 마이페이지에 둔다(예정).
- 듣기 전 질문은 연령별로 나누지 않고 기사마다 하나만 쓴다(같은 기사·음원을 모두가 쓰고, 답을 받지 않는 생각거리라서). 초등 4학년도 이해할 말로, 정답이 없고 기사 내용을 미리 알려 주지 않게 쓴다.

인스타그램 게시물은 학습 1회에 1개다. 활동마다 따로 올리는 이유는 완주를 60회로 세기 때문이다. 활동별 중간 단계는 다를 수 있지만 학습 완료(completed_at)와 인증(verified_at)은 공통으로 관리한다. 중단된 활동은 언제든 이어서 할 수 있어야 한다.


## 7. 학생 홈과 메뉴

화면 아래에 탭 메뉴 4개를 고정한다: **홈**, **이번 주 자료**, **인스타 올리기**(올릴 것 개수 표시), **내 기록**(2026-10-09 추가). 자료·올리기·내 기록은 홈에 따로 진입점을 두지 않고 탭으로만 들어간다.

**내 기록 탭과 뉴스북 (2026-10-09)**
- 학습자별로 보인다(형제는 이름 버튼으로 학습자를 바꿔 각자 기록을 본다).
- 이번 기수 뉴스북 카드(기사 N / 12 실림, 뉴스북 보기), 이번 기수 기록(낭독·읽은 기사·쓴 요약·낸 의견·주간 목표 달성 주 수), 지난 기수(재수강생, 기수별 기록과 뉴스북), 설정(사진 글자 읽기 AI 동의, 보호자만 바꿈).
- 뉴스북은 기수별 1권. **진도 중간에는 화면으로 열람만, 종강 다음 날(한국 시간 0시)부터 PDF 다운로드.** PDF는 누를 때 서버에서 만들고 보관하지 않는다.
- 구성: 표지(이름의 영어 뉴스북, 과정·기수, 기간, 읽은 기사 수) → 이번 기수의 기록 → 기사별 쪽(날짜·원래 기사 제목, 뉴스 카드 = 내가 붙인 제목·요약·"기자 이름"·손글씨 사진, 의견 카드 = 입장·이유, 찬반 결과 막대) → 내가 붙인 제목 모아보기.
- 기사 쪽의 요약은 그 주차에 가장 최근 완료한 기사 요약, 의견은 마지막으로 고른 입장. 찬반 결과는 의견을 고른 주차에만 싣는다. 의견이 없으면 의견 카드를 뺀다.
- 기록이 없는 주차: 화면에서는 "아직 비어 있어요"로 보여 주고(이번 주에 채우도록), PDF에서는 뺀다(기획 회의에서 확정 필요).
- 손글씨 사진은 보관 기간(종강 후 3개월) 안에만 들어간다. 이달의 앵커 자격은 앵커 기능을 만들 때 기록에 더한다.

홈에는 다음만 둔다.

- 라이브 카드: 라이브 3일 전부터 맨 위에 표시(13장).
- 주차 카드: "4주차", 기사 제목, "이번 주 학습 3 / 5", 학습 완료 동그라미 5개. 게시 상태는 표시하지 않는다.
- "+ 오늘 학습하기" 버튼 하나.
- 완주 카드: 종강일과 남은 주(예: 종강 12월 6일(일) · 9주 남음)를 가장 크게, 그 아래 "완주까지 인스타 올리기 15 / 60"과 진행 막대. 보상 내용(뱃지, 낭독 비교)은 미리 설명하지 않는다.
- 12주 기록: 기본은 접힌 상태로 "학습 17 / 60 · 3주차 1회 남음" 한 줄만 보인다. 누르면 12주 × 5칸 = 60칸이 펼쳐져 미션 전체 규모를 한눈에 보여준다.
- 60칸은 활동 종류별 열을 나누지 않는다(같은 활동을 5번 해도 되므로). 학습한 칸에는 그 활동의 아이콘을 넣는다: 한국어 기사 읽기(말풍선 + 가), 영어 기사 읽기(말풍선 + A), VOCA(겹친 카드), 기사 요약(줄 그은 문서), 찬반토론(저울). 칸 위에 아이콘 설명을 둔다.
- 칸 상태: 학습함(청록 칸 + 아이콘), 지난 주차 빈칸(점선, 언제든 채울 수 있음), 이번 주 빈칸(실선), 앞으로의 주차(회색). 지난 주차·이번 주 빈칸을 누르면 그 주차가 선택된 활동 고르기로 간다(2026-10-09). 같은 활동을 여러 번 하면 완료 순서대로 칸마다 그 아이콘이 반복되고, 한 주 5칸을 넘는 학습은 칸에 보이지 않지만 횟수에는 들어간다.

- 홈에서 뺀 것: 게시 대기 띠, "이어서 하기" 버튼, 활동 분포 칩, 자료 링크. 작성 중인 활동은 활동 선택 화면에 "작성 중 · 이어서"로 표시한다.
- 마감 이후 홈은 유예 중(남은 인증 수, 올리기 버튼)과 유예 종료 후 두 상태로 바뀐다(2026-10-09 구현). 유예 중: "12주 챌린지가 끝났어요. 조금만 더 하면 완주예요! / ○월 ○일(일)까지 남은 N개를 올리면 완주 상장과 함께 첫 낭독 다시 듣기를 받을 수 있어요." 유예 끝: "아직 완주할 수 있어요 / 남은 N개를 올리면 완주 상장을 받아요. 아직 올리지 않은 녹음은 (종강 + 3개월)까지 보관돼요." 그 아래 인스타 올리기 진행, 올릴 것 올리기·학습하기 버튼, 12주 기록.
- 완주하면(인증 60회) 홈 맨 위와 내 기록에 "12주 완주" 카드가 생겨 완주 화면으로 간다. 60번째 인증 직후에는 완주 화면으로 바로 이동한다.
- 이전 활동을 마쳐야 다음 활동을 할 수 있는 직렬 구조는 금지한다.


## 8. 낭독 활동 루프

1. 자료·음원 확인: 원문(영어 문단 + 한글 해석)과 음원을 먼저 접한다.
2. 듣기 단계에 기사별 **듣기 전 질문**을 하나 보여 준다(콘텐츠 시트 기사 탭 "듣기 전 질문" 칸, 답은 받지 않음, 2026-10-09). '녹음'보다 학습 행위를 강조하는 '낭독 시작' 버튼을 쓴다. 이어폰 사용을 한 줄로 안내한다.
3. 3초 카운트다운 후 녹음을 시작한다.
4. 녹음 중에는 경과 시간과 최소한의 상태만 표시한다.
5. 종료 후 다시 듣기, '다시 읽기 / 이대로 완료 / 완료하고 바로 올리기' 중 선택한다. 완료를 누르면 "이 낭독으로 제출할까요?"로 한 번 더 확인하고, 제출한 낭독만 학습 1회로 센다(2026-10-09 결정, 낭독 횟수 집계 기준과 같음).
6. 주차별 템플릿 이미지와 녹음을 결합해 인스타그램 게시용 MP4를 만든다. 휴대폰(브라우저)에서 만들며 서버에는 저장하지 않는다(10장). 이 기능은 2단계 영상 합성 모듈로 따로 만든다(19장 개발 단계).
7. 녹음 최대 길이는 휴대폰에서 영상 합성이 안정적으로 되는 길이로 정한다. 값은 2단계 기기 시험 결과로 확정하고, 앱은 설정값 하나로 읽는다. 최대 길이에 가까워지면 남은 시간을 안내하고, 도달하면 자동으로 정지한다(녹음 후 잘라내지 않는다).
8. 인스타 올리기 탭에서 저장 → 인스타그램 업로드 → 게시물 링크 붙여넣기로 인증한다. 낭독은 "영상 저장", 작성지 활동은 "사진 저장" 버튼을 보여준다.

사용자는 낭독만 매일 하고 업로드는 며칠치를 몰아서 할 수 있다. 학습 완료와 인증 완료는 반드시 별도 상태로 저장한다.


### 하이라이트와 속도

- **속도**: 0.5 / 0.8 / 1 / 1.2배. 학습자가 고른 속도를 기억해 다음에도 그 속도로 시작한다. 재생 속도만 바꾸고 목소리 높이는 유지한다.
- **청독 하이라이트**: 음원 재생 위치(currentTime)를 기준으로 지금 읽는 덩어리를 칠한다. 속도를 바꿔도 음원 기준 시간이라 어긋나지 않는다.
- **낭독 하이라이트**: 녹음 중에는 음원을 틀지 않고, 같은 시간 정보를 고른 속도로 늘이거나 줄여 하이라이트만 움직인다. "잠깐 멈추기", "하이라이트 끄기"를 둔다.
- **단위**: 영어는 끊어 읽기 구 단위("/"로 표시), "/"가 없는 문장은 문장 단위. 한국어는 문장 단위. 한영 구간반복은 한국어 문장 → 영어 문장 2회 순서로 문장 단위.
- **끊어 읽기 표시**: 화면에 "/"를 보여줄지 학습자가 켜고 끌 수 있다. 기본은 꺼짐.
- **시간 정보**: 음원마다 단어 단위 시간 정보 파일 1개. 자료 반영 때 일레븐랩스 강제 정렬(Forced Alignment)로 만든다. 정렬할 때는 "/"를 뺀 원문을 쓴다. 정렬 신뢰도 점수가 낮으면 자료 반영 오류 목록에 띄운다.
- **원문 일치**: 자료 시트의 영어·한국어 원문은 음원 대본과 글자 그대로 같아야 한다. 숫자, 약어(SFMOMA 등), 기호는 음원에서 읽는 방식을 미리 정한다.
- **예상 시간**: 낭독 시작 버튼 위에 고른 속도 기준 예상 낭독 시간을 보여준다.
- **난이도 표시**: 렉사일(추정치는 "난이도"로 표기)과 본문 단어 수는 낭독 화면이 아니라 이번 주 자료 탭의 기사 제목 아래에 작게 둔다. 누적 낭독 단어 수(영어 낭독 학습 완료 × 그 주차 기사 단어 수, 한국어 낭독은 세지 않음)는 12주 기록 펼침과 완주 화면에 보여준다.


## 9. 첫 낭독과 마지막 낭독

- 별도 지문이나 별도 이벤트를 두지 않는다. 해당 주차 기사를 읽는다.
- 첫·마지막 낭독 파일을 따로 장기 보관하지 않는다. 인스타에 올린 영어 낭독 중 가장 이른 것과 가장 늦은 것을 첫·마지막 낭독으로 정하고, 그 게시물 링크(post_url)를 기억한다.
- 완주 화면에서는 녹음 보관 기간(종강 후 3개월) 동안 앱에서 두 녹음을 나란히 재생하고, 각 낭독 옆에 "인스타 ›" 링크를 둔다. 보관 기간 이후에는 인스타 링크로만 연결한다.
- 게시물을 지우거나 계정을 비공개로 바꾸면 링크가 열리지 않을 수 있다. 이 경우 완주 화면에서 해당 낭독을 "볼 수 없음"으로 표시한다.
- 첫 영어 낭독을 완료하면 팝업으로 한 번 알린다: 인스타에 올리면 그 게시물을 첫 낭독으로 기억해 두고, 종강일까지 완주하면 마지막 낭독과 나란히 들려준다.
- 12주차에는 홈에서 마지막 영어 낭독을 권유한다. 강제는 아니다.
- 지문이 달라 정밀 비교는 어렵지만 매끄러움과 자연스러움의 변화를 체감하는 것이 목적이다.
- 제때·유예 완주자의 완주 화면에서만 두 낭독을 들려준다. 마지막 낭독을 마친 뒤 첫 낭독을 공개한다.
- 완주 화면에는 총 인증 횟수, 활동별 횟수, 소리 내어 읽은 영어 단어, 두 낭독 재생, 상장 받기를 함께 보여준다(보상 PDF는 뺌). 완주 화면은 60번째 인증 직후, 홈의 완주 카드, 내 기록, 완주 알림톡에서 들어간다. 내 기록의 "이번 기수 기록"은 같은 모양의 진행 중 버전이다.


## 10. 파일 보관과 마감 이후

- **영상은 서버에 저장하지 않는다.** 서버에는 녹음과 작성지 사진만 보관하고, 영상은 "영상 저장"을 누를 때마다 휴대폰에서 녹음과 기사 이미지로 만든다.
- **파일 삭제를 완주 동기로 쓰지 않는다.** 제때 완주의 동기는 COMPLETE! 뱃지와 첫·마지막 낭독 비교로 충분하다.
- **보관 기간은 개인정보 기준으로 하나만 둔다.** 종강 후 3개월이 지나면 녹음과 사진을 모두 지운다.
- 보관 기간 안에는 늦은 완주자도 남은 기록을 그대로 올려 완주할 수 있다.
- 보관 기간이 지난 뒤 올리지 않은 기록은 같은 기록에서 "다시 녹음해서 올리기"(작성지 활동은 사진 다시 올리기)로 처리한다. 새 학습으로 세지 않으므로 학습 횟수가 부풀지 않는다.
- 종강 전에는 삭제를 언급하지 않고 "종강일까지 모두 올려 주세요"만 안내한다. 보관 기간은 종강 예고 알림톡과 종강 이후 홈에서 알린다.
- 출석·활동 기록(메타데이터)은 파일 삭제와 무관하게 보관한다.


## 11. 첫 접속과 다시 들어가기

흐름: 아임웹 결제 → 결제 신호로 주문 기록 → 보호자(결제자) 번호로 결제 완료·시작 안내 알림톡(보호자 접속 링크) → 첫 접속 3단계 → 홈.

1. **환영**: 신청 정보 확인(과정명 예: 새벽달 영어뉴스 1기, 기간은 "12주"로만 표시, 신청 연락처), 제공 자료 확인(PDF 2종, 음원 3종, Zoom Live 횟수, 이름만 보여주는 확인용이며 내려받기는 없음), 보호자 정보 입력(이름, 알림톡 수신 동의), 홈 화면 바로가기 추가 안내(아이폰/안드로이드, 카카오톡 인앱 브라우저에서 열렸을 때 외부 브라우저로 여는 법).
2. **학습자 등록**: 이름, 출생 연월(학년 자동 표시), 인스타그램 ID. 형제·자매 추가 등록.
3. **접속 방법과 동의**: 자녀 본인 휴대폰 사용 여부. "예"면 자녀 연락처 입력 후 자녀에게 링크 발송. 음성·이미지 수집 보호자 동의.

- 자녀는 받은 링크로 등록 과정 없이 바로 홈에 들어온다.
- 한 번 들어온 브라우저는 기억해 두어 링크 없이도 열린다.
- 링크를 잃어버리면 "다시 들어가기"에서 등록 번호를 입력하고, 그 번호로 새 링크를 알림톡으로 받는다. 화면에서 바로 로그인시키지 않으며, 번호의 등록 여부도 드러내지 않는다.
- 접속 링크에는 전화번호 대신 무작위 토큰을 쓴다.

접속 방식 결정 (2026-10-08, T04)
- **로그인 화면은 두지 않는다. 알림톡 링크로만 들어온다.** 연락처 + 인증번호 로그인은 만들지 않는다.
- 보호자 링크는 학습자가 아니라 **보호자(결제자)**에 붙는다. 결제 직후 학습자가 없어도 링크를 보낼 수 있고, 보호자 링크 하나로 자녀(형제) 전부를 고른다. 자녀 링크는 그 자녀 한 명만.
- 알림톡 버튼은 **외부 브라우저로 열기**로 설정한다(솔라피 버튼 설정). 아이폰은 Safari, 안드로이드는 기본 브라우저로 열린다.
- 링크로 들어오면 주소에 링크 문자열을 남겨 둔다. **홈 화면에 추가하면 아이콘이 링크를 품고 있어** 열 때마다 들어온다(브라우저 기록이 지워져도). 그래서 홈 화면 앱 안에서 로그인이 풀리는 일은 링크 폐기·만료·아이콘 삭제 외에는 없다.
- 다시 들어가기 = 번호 입력 → 그 번호(보호자 또는 자녀 본인 번호)로 **새 링크** 알림톡. 인증번호는 없다. 새 링크를 보내도 이전 링크는 살려 둔다(기존 홈 화면 아이콘 유지). 같은 번호 반복 요청은 막는다.
- 링크는 여러 번 쓸 수 있고, 마지막 기수 종강 후 3개월(보관 기간 끝)까지 유효하다.
- **주문 1건 = 한 가정.** 자녀가 여럿이어도 함께 참여하며, 등록 인원과 결제 금액은 대조하지 않는다.
- **결제자 본인 혼자 학습할 수 있다**("저 혼자 학습해요"). 고르면 형제·자매 추가 버튼을 숨긴다. 한 가정에 1명. 이름은 보호자 이름(고칠 수 있음), 학년 대신 "성인", 출생 연월·자녀 휴대폰 질문 없음, 동의 문구는 본인용.
- 형제는 아임웹 주문 1건(결제자 1명). 자녀가 몇 명 함께하는지는 결제 시점이 아니라 **자녀 정보를 등록할 때** 정해진다. 첫 접속 2단계에서 1명부터 시작해 "형제·자매 추가"로 **최대 4명**까지 등록하고, 나중에는 홈의 이름 버튼 → 프로필 화면에서 추가한다(홈에 추가 버튼을 상시로 두지 않는다). 재수강생은 새 학습자를 만들지 않고 지난 기수 학습자를 골라 등록한다.
- 구글폼은 이 등록 화면으로 대체하는 것을 전제로 설계했다(최종 확인 필요).


## 12. 알림톡 정책

> 원칙: 알림톡은 꼭 필요한 순간에만 보낸다. 매주 보내는 기사 안내는 하지 않는다. 진도가 더딘 학생에게도 기수당 2~3회를 넘겨 독촉하지 않는다. 그 이상은 본인이 따라갈 수 없는 사정이 있는 것이고, 더 보내면 압박이 된다.


### 진도 중 알림톡

| 알림톡 | 시점 | 대상 | 횟수 | 내용 |
| --- | --- | --- | --- | --- |
| 시작 안내 | 결제 후, 기수 시작 전 | 결제 보호자 | 1회 | 접속 링크, 시작일, 종강일(12주차 일요일) |
| 진도 독려 | 2·4·7주차 월요일 | 학습이 밀린 학습자 | 기수당 최대 3회 | 밀린 횟수, 지난 주차도 채울 수 있다는 안내, 앱 링크 |
| 라이브 당일 | 라이브 당일 오전 | 전체 학습자 | 라이브 회차 수 (2회 → 1회) | 시작 시각, 앱 라이브 카드 링크 |
| 종강 예고 | 12주차 시작(월) | 전체 학습자 | 1회 | 종강일, 개인별 남은 올리기 수, 올리지 않은 녹음의 보관 기간(종강 후 3개월) |


### 진도 독려 기준

밀림은 **학습 완료 기준**으로 판정한다. 인증(게시)이 밀린 것은 독려 대상이 아니다. 밀린 양 = 그 시점까지 기대 횟수(지난 주차 수 × 5) − 누적 학습 완료 횟수(소급분 포함).

| 회차 | 발송 | 대상 | 판정 예시 |
| --- | --- | --- | --- |
| 1차 | 2주차 월요일 오전 | 1주 분량(5회) 이상 밀림 | 기대 5회 중 학습 완료 0회 |
| 2차 | 4주차 월요일 오전 | 2주 분량(10회) 이상 밀림 | 기대 15회 중 5회 이하 |
| 3차 | 7주차 월요일 오전 | 3주 분량(15회) 이상 밀림 | 기대 30회 중 15회 이하 |

- 회차마다 독립적으로 판정한다. 1차를 받지 않은 학습자도 2차 대상이 될 수 있다.
- 7주차 이후에는 진도 독려를 보내지 않는다. 그 이상 밀린 경우는 본인이 따라갈 수 없는 사정이 있는 것으로 보고 압박하지 않는다.
- 환불한 수강은 제외한다.


### 받는 사람

| 알림톡 | 보호자 휴대폰으로 진행 | 자녀 본인 휴대폰으로 진행 |
| --- | --- | --- |
| 시작 안내 | 보호자 | 보호자 (자녀 등록 전이므로) |
| 진도 독려, 라이브 당일, 종강 예고, 완주 상장 | 보호자 | 보호자와 자녀 모두 |
| 자녀 접속 링크 | 해당 없음 | 자녀 |
| 새 접속 링크 | 요청한 번호 | 요청한 번호 |

- 두 번호로 보내도 1회로 센다. 독려 상한은 발송 메시지 수가 아니라 회차 기준이다.
- 형제가 함께 밀린 경우 보호자는 학습자별로 각각 받는다. 문구에 학습자 이름을 넣는다.


### 요청·사건 기반 알림톡 (진도 알림이 아님)

- 자녀 접속 링크: 보호자가 자녀 연락처를 등록했을 때.
- 새 접속 링크: "다시 들어가기"를 요청했을 때.
- 완주 상장 안내: 인증 60회를 채웠을 때. 링크는 상장 이름 확인 화면으로 연결한다.


### 운영 규칙

- 진도 독려는 회차별로 한 번만 보낸다. 관리자 대시보드에서 수동으로 보내는 독려도 총 3회 상한에 포함하며, 상한에 닿은 학습자는 이후 자동 발송에서 빠진다.
- 라이브 알림톡 링크는 Zoom이 아니라 앱 라이브 카드로 보낸다. 입장 클릭을 기록하고, Zoom 링크가 바뀌어도 재발송이 필요 없다.
- 알림톡 문구 템플릿은 카카오 사전 승인이 필요하므로 일정에 반영한다.

### 규칙

- 재수강 여부는 저장하지 않고 수강 2건 이상으로 계산한다.
- **지금 기수**(홈·활동·자료·올리기가 보여 주는 기수): 환불하지 않은 수강 중 이미 시작한 기수의 가장 최근 것. 시작한 기수가 없으면(개강 전 신규) 가장 최근 기수. 재수강생이 다음 기수를 결제해도 그 기수가 시작하기 전까지는 진행 중인 기수를 보여 준다(2026-10-09). 지난 기수는 마이페이지의 보고서 형태로 보고, 종강 뒤 일정 기간은 올리기도 허용한다(기간 확정 필요).
- 수강 상태(enrollments.status): paid(이 상품·기수를 결제함) / refunded(환불·과정 취소 완료).
- 환불 처리(enrollments.refund_status): 관리자가 확인 후 수동으로 처리한다. requested(요청 접수·확인 대기) → approved(환불 완료, refunded_at 기록, status = refunded) 또는 rejected(환불 불가). 접속 링크 폐기는 approved일 때만.
- 전화번호는 숫자만 저장한다(예: 01012345678).
- 학년은 birth_ym으로 계산하고, 수강 당시 학년은 grade_at_enrollment에 남긴다.
- 횟수는 저장하지 않고 계산한다. 주간 학습 = 해당 주차 completed_at 건수, 완주 진행률 = verified_at 건수 ÷ 60, 게시 대기 = completed_at은 있고 verified_at은 없는 건수.
- completion_tier: 60번째 verified_at이 deadline 이전이면 on_time, grace_until 이전이면 grace, 그 이후면 late.
- 진도 독려 횟수 = 해당 enrollment의 "진도 독려" 알림 중 서로 다른 checkpoint 수. 3이면 더 보내지 않는다. 같은 checkpoint는 두 번 보내지 않는다.
- 환불 처리 시 해당 수강의 접속 링크를 자동으로 폐기한다. 단, 같은 학습자에게 환불하지 않은 다른 수강(재수강의 지난 기수 등)이 남아 있으면 링크는 유지하고, 환불한 기수의 페이지(수강·기록·주차·자료)만 보이지 않게 한다(2026-10-07 결정).
- 접속 링크는 원문을 저장하지 않고 token_hash만 저장한다.
- 비상용 시트에는 수강생 목록, 학습·인증·게시 대기 횟수, 완주 단계, 최근 활동일, 마지막 갱신 시각을 담는다. 토큰과 파일 주소는 뺀다. 공유는 운영팀 계정으로 제한하고, 비상시 수정은 시트의 "수동 처리" 탭에 기록한 뒤 복구 후 대시보드에서 반영한다.


## 17. 학습 자료 운영

1. 운영자가 자료 시트에 기사·문단별 해석·단어·파일 이름을 입력한다.
2. 음원과 PDF는 기수 폴더에 넣는다. 드라이브 "새벽달 영어뉴스 웹앱 게시 자료" 아래 기수마다 폴더(1기, 2기 …)를 하나씩 두고, 그 기수의 콘텐츠 시트와 모든 주차 파일을 한 폴더에 넣는다. 파일명은 `news<기수 2자리>_week<주차 2자리>_<종류>.<확장자>`(2026-10-08 결정, 규칙 안내는 같은 상위 폴더의 "새벽달 영어뉴스 자료 파일명 규칙" 문서).
3. 검수가 끝나면 기사 상태를 "공개"로 바꾼다.
4. 관리자 화면의 "자료 반영" 버튼(또는 정해진 주기)으로 동기화하면 DB와 Storage로 복사된다.
5. 학생 앱은 DB와 Storage에서만 읽는다.

- 동기화 전 검사: 빈 문단, 영어·한글 중 한쪽만 있는 문단, 폴더에 없는 파일, 공개일이 됐는데 "공개"가 아닌 기사. 문제가 있으면 반영하지 않고 관리자 화면에 목록으로 보여준다.
- 음원 규격: MP3 또는 AAC 모노 64~96kbps. 규격이 다르면 변환하거나 경고한다.
- 파일을 바꾸면 새 version으로 올리고 연결만 바꾼다. 같은 파일은 브라우저 캐시를 허용한다.
- 드라이브 공유 링크를 재생에 직접 쓰지 않는다. 다운로드 제한, 아이폰 재생·구간 이동 실패, 예고 없는 동작 변경, 유료 자료 노출 위험이 있다.
- VOCA 단어 목록(앱)과 VOCA 작성지 PDF는 주차 시작부터 공개한다.
- **자료는 주차별로 순차적으로 열린다**(2026-10-08): 미리 반영해 두어도 그 주차 시작(월 0시) + 기사 "공개"일 때만 학생에게 보인다. 이번 주 자료 탭은 열린 주차만 고를 수 있고 다음 주차가 열리는 날을 안내한다.
- 주차(기사)별 **추가 자료**: 링크(https)와 안내 텍스트를 콘텐츠 시트에서 넣으면 그 주차 자료에 함께 보인다(`week_items`). 시트 반영 방식은 `docs/tasks/T05-콘텐츠-시트-반영.md`.

## 18. 미확정 및 검증 필요

- 인스타그램 인증 방식: 링크 제출만으로 인정할지, 비공개 계정은 어떻게 처리할지. 개인 계정 자동 게시는 불가로 보고 있으나 공식 정책 확인 필요.
- 녹음 최대 길이: 휴대폰 합성이 안정적인 길이로 2단계 기기 시험에서 확정. 기사는 170~200단어라 아이 낭독이 3분을 넘을 수 있다. 확정 전 임시값 5분.
- 인스타 영상 비율: 게시물 4:5(1080×1350) / 릴스 9:16(1080×1920). 템플릿 디자인과 함께 결정.
- 인스타 템플릿 이미지 규격: 1080×1350(4:5) PNG 가정. 학습자 이름 등 글자를 얹을지 여부.
- 카카오톡 인앱 브라우저에서 마이크 녹음, 음원 재생, 영상 저장이 되는지 실기기 테스트(아이폰 Safari·홈 화면 바로가기, 안드로이드 Chrome 포함).
- 만 14세 미만 학습자의 음성 수집에 대한 보호자 동의 절차와 동의 문구(법률 검토).

- 최소 녹음 길이를 둘지 여부.
- 카메라 영상 녹화 + 템플릿 합성: 첫 출시에서 제외. 도입 시 영상 보관 위치, 얼굴 영상 동의, 다시 만들기 불가 문제를 함께 결정.
- 완주 상장의 제때·유예·늦은 완주 디자인 차이.
- 첫 접속 화면의 보호자 정보 항목(현재: 이름, 알림톡 수신 동의).
- 구글폼 폐지 확인(현재 설계는 웹앱 등록 화면으로 대체).
- 기수·상품별 weekly_target 변경 허용 여부(테이블은 대비되어 있음).
- 재수강생의 기수를 넘는 낭독 비교(선택 사항, 보관 기간·동의 필요).

- 인스타 게시물 링크가 실제 게시물인지 검증할지(18장 첫 항목과 함께 결정).

```
낭독 챌린지 웹앱의 데이터 계층을 만든다. 화면은 아직 만들지 않는다.

기준 문서: 낭독 챌린지 컨텍스트 및 작업지시서 (통합본). 이 문서만 따른다.
규칙을 짐작해서 채우지 말고, 문서에 없는 결정이 필요하면 멈추고 질문 목록으로 남겨라.

1. Supabase(PostgreSQL) 마이그레이션 작성
   - 16장의 회원·수강·기록 테이블 9개와 학습 자료 테이블 5개
   - 외래 키, 인덱스(activities의 enrollment_id + week_no, verified_at 여부)
   - 환불 시 access_tokens 자동 폐기

2. 집계 뷰 작성 (횟수는 저장하지 말고 계산)
   - 학습자별: 이번 주 학습, 누적 학습, 인증 수, 게시 대기, 완주 단계
   - 관리자 목록용: 학습 밀림, 게시 밀림, 진도 독려 받은 회차
   - 진도 독려 대상 판정: 12장 기준(2·4·7주차 월요일, 학습 완료 기준 밀린 양)
   - 알림 받는 사람 결정: 12장 받는 사람 표
   - completion_tier 판정: on_time / grace / late

3. 샘플 데이터
   - 1기, 12주, 기사 12편(본문은 자리표시 텍스트), 학습자 8명
   - 정상, 학습 밀림, 게시 밀림, 미시작, 형제 수강, 자녀 본인 접속, 환불, 재수강, 늦은 완주 사례 포함

4. 검증
   - 샘플 데이터로 집계 결과가 문서 규칙과 맞는지 확인하는 테스트
   - 결과와 남은 질문을 README에 정리

저장소 접근 코드는 한 모듈에 모아, 나중에 Supabase Storage에서 R2로 바꿀 수 있게 한다.
```
